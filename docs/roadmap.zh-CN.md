# 社区路线图

[English](roadmap.md)

以下是建议共建方向，不是发布日期承诺。请从一个聚焦的 Issue 开始，并附产出的验证证据。

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 | 独立安装复现 | 另一位贡献者从全新 checkout 构建，记录宿主/工具版本、缺失步骤和结果 |
| 1 | 客体准备流水线 | 确定性流程接受用户提供的原始输入，核验身份，只生成派生文件，并到达正常诊断入口 |
| 1 | 应用兼容报告 | 一个原版应用拥有可复现的启动、交互、退出及相关像素/身份检查 |
| 1 | macOS 打包及独立分发验证 | 构建的应用移动目录后无依赖加载错误；所有打包库均有源码及许可来源 |
| 2 | Linux 宿主调查 | 给出构建/显示策略与有界板级或渲染结果；仅可移植主机测试通过不够 |
| 2 | GLES 正确性 | 缺失或错误调用拥有最小客体复现、内存/生命周期检查及正负回归 |
| 2 | 设备模型准确性 | 有界复位、中断、时钟或存储行为关联源码/资料，测试不破坏默认客体 |
| 3 | 扩大 UX 验证 | 明确的一种键盘语言、方向或长会话拥有可重复证据及范围说明 |
| 持续 | 双语文档 | 两种语言说明相同支持路径，并通过本地链接检查 |

适合初次参与：根据真实安装失败改进错误提示、补充某个输入的来源、修正翻译或提交脱敏兼容报告。底层图形和设备工作需要更窄的提案及更强的验证，不需要更大的首个 PR。

可再分发客体镜像属于独立工作：每个组件都需要明确来源和权限依据。本项目不以直接托管量产固件作为捷径。
